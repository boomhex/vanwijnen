# Extraction Eval

This golden eval compares offer extraction output against golden snapshots.

It does not make LLM calls or re-extract PDFs. Fuzzy matching is only used to
pair expected posts with actual posts for scoring; the expected extraction data
remains explicit and reviewable in `testcases/*.json`.

Run:

```bash
env PYTHONPATH=development/app venv/bin/python development/evals/eval_posten/main.py
```

Each testcase in `testcases/*.json` contains:

- `ExtractPath`: the current actual `extract.json` to evaluate
- `Expected`: the golden extraction result to compare against

The scorer uses fuzzy matching to pair expected posts with actual posts, but the
expected data remains explicit and reviewable in the golden testcase files.

Generate a golden testcase from an existing extract:

```bash
env PYTHONPATH=development/app venv/bin/python development/evals/eval_posten/main.py \
  --generate-from-extract app/storage/test/22.31_baksteen/postma/extract.json \
  --overwrite
```

Primary metrics:

- `post_recall`: expected posts found in the actual extraction
- `post_precision`: actual posts that match expected posts
- `field_accuracy`: checked post fields that match after normalization
- `rich_schema.coverage`: coverage of the newer matching-oriented post fields

## Before/after a prompt or extraction-code change

The default run above only re-scores whatever `extract.json` already happens
to be on disk — it does **not** by itself prove a prompt change helped, since
that stale file was generated by the *old* prompt.

To actually compare before/after a prompt change:

```bash
# 1. Baseline run against the current (pre-change) extract.json files.
env PYTHONPATH=development/app venv/bin/python development/evals/eval_posten/main.py --run-name before

# 2. Make your prompt/extraction-code change.

# 3. Re-run extraction for the eval PDFs with the new prompt (real Gemini
#    calls, needs GEMINI_API_KEY set), then score the fresh output.
env PYTHONPATH=development/app venv/bin/python development/evals/eval_posten/main.py --regenerate --run-name after

# 4. Compare runs/before/report.md against runs/after/report.md.
```

`--regenerate` overwrites each testcase's `ExtractPath` extract.json in place
by re-running `services.extract_offer.extract_offer` against its
`document.pdf`, then scores the fresh result — so `runs/after/` reflects the
prompt you're about to ship, not a leftover snapshot. This costs real API
calls, so it's opt-in and never runs by default.

## A caveat about the golden data itself

The `Expected` block in each testcase was generated **from a prior
extraction's own output** (via `--generate-from-extract`), not independently
verified against the source PDF. That means this eval is a **regression**
check (did output change since the snapshot was taken?), not a ground-truth
correctness check — a systematic mistake the model already made can be
"golden" here and would never show up as a failure. If you're relying on
these scores to judge extraction quality (not just detect drift), spot-check
a few `testcases/*.json` against their `document.pdf` by hand first, and
correct the `Expected` block where it's wrong.
